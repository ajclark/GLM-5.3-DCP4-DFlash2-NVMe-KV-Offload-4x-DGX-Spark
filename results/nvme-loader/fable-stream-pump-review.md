**Verdict on the pump:** the design is correct. Single producer advances the Run:ai generator, the semaphore plus one-slot queue give exactly one tensor of lookahead, cancellation is explicit, the inner generator is only ever closed by the thread that runs it, `record_stream` on the consumer stream is the right call for a tensor allocated on the pump thread's stream, and `put` dropping on `stop` cannot lose an item the consumer is waiting for. I found no newly introduced correctness bug in the streaming path. Four items worth fixing before the GPU run, in priority order.

**1. The 30-second join aborts a successful load if streamer teardown is slow.**
In `runtime/nvme_loader/spark_nvme/streaming.py:151` the `finally` runs on the normal `done` path too. At that point the pump is inside `iterator.close()`, which runs the inner generator's cleanup and Run:ai's `__exit__`. If that exceeds 30 s after a complete 405 GB stream, the consumer raises "stream producer failed to stop" and the worker dies with all weights placed. Also, any exception raised by `iterator.close()` in the pump's `finally` at line 135 is lost, because the `done` message was already sent; the load then reports complete with a swallowed teardown error. Fix: track whether the loop ended with `done`; on that path join without a deadline, or with a long one, and only treat a timeout as fatal on the cancellation path. Wrap `iterator.close()` in the pump with `try/except` that records the exception into the shared metrics as `teardown_error`, and have the loader treat a non-empty `teardown_error` as a failed source.

**2. Lookahead consumes owned budget that the draft can no longer spare.**
Live owned bytes now include the tensor the consumer holds, the queued tensor, and the one the pump is copying, in addition to whatever the model retains. With the draft retaining its full 4.92 GB and two 453 MB lookahead tensors, live reaches about 5.8 GB against a 6 GiB limit, so `reserve` at line 178 is within a few hundred megabytes of aborting the draft again. Either raise the default to 8 GiB or make the retention allowance explicit: reserve `2 * largest` for lookahead and apply the configured limit to the remainder. The loader's early fallback check at `runtime/nvme_loader/spark_nvme/loader.py:177` should use the same arithmetic so it agrees with the runtime check.

**3. A join timeout hides the original failure in the receipt.**
When the consumer is unwinding because the model raised and the pump is blocked inside a C++ read, the `RuntimeError` from line 155 replaces the model's exception; Python chains the original as `__context__`, but the receipt at `loader.py:214` formats only the outer exception, so every rank's error reads "stream producer failed to stop". Include the chained cause in the receipt text, for example by walking `__context__` and appending the first non-`RuntimeError` message.

**4. Verify that the Run:ai wait releases the GIL, or the pump provides no overlap.**
`next(iterator)` runs the Run:ai `get_tensors` generator on the pump thread. If the C++ `get_chunks` blocks while holding the GIL, the consumer's Python placement work cannot run during reads and the pump degrades to strict alternation, with the consumer's own progress stalled. The metrics already record `reader_wait_seconds` and `producer_backpressure_seconds`; add the consumer-side time between yields back into the progress line so the first GPU run shows whether reader wait and consumer time overlap or sum. This is a check, not a code defect.

Two things I confirmed are fine and would otherwise look suspicious. `slot.release()` on the `done` and `error` messages pushes a plain `Semaphore` above its initial count, which is harmless because the pump has exited. Closing the prefetch generator before its first `next` never starts the thread, so the never-iterated case leaks nothing, and the early-termination case is caught by the `complete` check in `_load` even though the pump lingers until garbage collection closes the outer generator; if you want that deterministic, keep a reference to the prefetch iterator on the loader and close it explicitly after `super().load_weights` returns.
