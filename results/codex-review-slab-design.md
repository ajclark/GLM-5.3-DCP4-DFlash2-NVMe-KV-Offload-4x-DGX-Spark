Verdict: fix these first. The lean approach can satisfy the intended cache invariant under the stated healthy-storage assumption, but this implementation has wrong-byte paths. Sequence validation, cross-rank startup validation, and payload CRC need not be reinstated to fix the issues below.

References: M = [multinode.py](/home/napta2k/spark-cluster-mla-dcp/overlay/vllm/v1/kv_offload/tiering/multinode.py); S = [connector scheduler.py](/home/napta2k/lmcache-mg/spark-src/vllm/distributed/kv_transfer/kv_connector/v1/offloading/scheduler.py).

1. **P1 — Failed loads release slots prematurely.** M:1468–1475 frees slots on the first rank’s failure, before all ranks complete (M:1635–1647; S:1091–1101), ignoring remaining load references. A reader can validate A’s header, then read B’s replacement payload successfully (M:1272–1283). Other chunks or concurrent loads can therefore receive wrong bytes; ordinary LRU pinning does not protect this path. Make failed keys immediately miss, but retain their slots until every reader completes. Memory-only reproduction confirmed reuse with a positive load reference and successful `read(A)` returning B.

2. **P1 — Header writes accept short writes.** M:1258,1267 ignore return counts despite the [short-write contract](https://www.man7.org/linux/man-pages/man2/pread.2.html). Fault injection reproduced: an 8-byte blank followed by a 32-byte final header leaves A’s old key over B’s complete payload; rebuild indexes A and `read(A)` returns B successfully. Require complete invalidation before writing payload and complete publication afterward. The blank/payload/header ordering is otherwise appropriate for process crashes under the lean reboot-wipe assumption.

3. **P1 — Flush timeout can remove the GPU reuse fence.** M:1004–1008 silently returns with jobs unfinished; M:1031–1032 exposes that as successful `wait()`. After sufficiently stalled I/O, the connector can reuse GPU source blocks while stores still need them, persisting new bytes under old keys. Timeout must raise or keep waiting. The slab enqueue hooks are wired correctly; failed disk-read chunks are not copied to GPU.

4. **P1 — Configuration identity is incomplete.** M:634–663 fingerprints target name, parallelism, dtype and block sizes, but omits drafter checkpoint identity and ordered tensor layout. Changing to a same-shaped drafter can reuse the same directory, hashes and lengths, serving previous-drafter KV as hits. Include those identities or explicitly invalidate on such changes.

5. **P1 — “Failure becomes recomputation” currently crashes for two groups.** Worker failure metadata and invalid GPU IDs are emitted (M:1674–1683), but the supplied [engine scheduler](/home/napta2k/lmcache-mg/spark-src/vllm/v1/core/sched/scheduler.py:2488) unpacks `(req_block_ids,)` from the multi-group block list at lines 2488–2489. A missing rank shard therefore raises instead of becoming a miss. No corresponding overlay fix was found. Implement group-aware recovery; test the real scheduler, which the current harness stubs.

6. **P2 — Placement is not transactional.** M:1413–1420 rollback returns slots but never restores evicted entries. With one slot holding A, `prepare_store([A,B])` skips A, evicts it, and stores only B; S:946 then advances past both. Preflight capacity and protect retained input keys. Calls larger than capacity cannot succeed by retrying. Duplicate input keys also leak slots; deduplicate while preserving order. M:1434 always reports no evictions. These produce misses/lost capacity, not inherently wrong bytes.

7. **P2 — Reset is incomplete.** M:1500–1501 makes reset-before-attach ineffective. M:1505 updates only the scheduler’s I/O epoch; workers read theirs once (M:1617), so post-reset stores disappear on restart. Reads ignore epoch (M:1274). Propagate the epoch with jobs. Separately, S:1229–1232 clears jobs but leaves active requests’ `transfer_jobs`; the next store can dereference a deleted job at S:955–957.

8. **P2 — Restart and capacity edges.** M:1364–1366 keeps the oldest duplicate despite its comment; worker counters restart at zero (M:1530), defeating chronological rebuild. Scan omits length/key-group validation, although normal reads reject wrong lengths. Shrinking the budget never truncates existing slabs (M:1609), violating the cap; M:1215 also exceeds undersized budgets. Torn metadata JSON aborts startup (M:1606). Treat unreadable metadata/unknown boot identity as an empty cache.

9. **P3 — Simplify sibling tracking.** M:1428 gives every target the batch’s drafter suffix, not its four siblings; lists multiply with batch size, survive failed stores, and vanish on rebuild. Remove this mechanism if simplicity wins: it affects hit rate only. Persisted LRU ordering and sync-for-durability are likewise unnecessary for byte identity.

Two slabs and 4:1 counts fit this deployment. Actual headers are 128 bytes; slot strides, not payload starts, are 4 KB aligned. That is compatible with buffered I/O. Sparse growth itself is sound; fix budget shrink and failure handling before deployment.
